# bob-benchmark

IBM Bob과 Claude Code, OpenAI Codex, Cursor를 기능별로 비교하는 사내 검토용 페이지.

메인 화면은 기능 × 도구 비교 장표 한 장이고, 표에서 기능을 누르면 그 기능에 대해 네 도구가
각각 어떤 역량을 갖는지 화면과 설명으로 비교한 상세 페이지로 이동합니다.

> **현재 상태: 가안.** 6개 카테고리 23개 항목을 채웠습니다. 판정은 공식 문서와 사내 발표자료를
> 근거로 작성했으나 아직 검증 전이며, Bob의 3개 칸은 근거를 찾지 못해 `확인 필요`로 비워 두었습니다.
> 검증 우선순위는 [PLAN.md 7장](PLAN.md)에 있습니다.

## 폴더 구조

```
public/                    ← 배포되는 파일은 전부 여기
├── index.html             장표 (메인)
├── detail.html            기능별 상세 비교 (?f=<slug>)
└── assets/
    ├── css/style.css
    ├── js/data.js         ← 비교 데이터 단일 소스
    ├── js/ui.js           두 페이지가 함께 쓰는 렌더 헬퍼
    ├── js/table.js        장표 렌더
    ├── js/detail.js       상세 렌더
    └── img/<slug>/        화면 캡처 / 영상
internal-src/              사내 원본 자료 (깃 제외 · 배포 제외)
wrangler.jsonc             Cloudflare 배포 설정
PLAN.md                    전체 계획과 배포 방법
```

`internal-src/`는 IBM 발표자료처럼 **공개 저장소에 올리면 안 되는 원본**을 두는 곳입니다.
`.gitignore`에 들어 있고, 배포 대상은 `public/` 하나뿐이라 Cloudflare로도 새지 않습니다.

빌드 도구가 없습니다. 파일을 고치고 새로고침하면 끝입니다.

## 기능 추가하기

[public/assets/js/data.js](public/assets/js/data.js)의 `FEATURES` 배열에 객체를 하나 추가하면
장표와 상세 페이지에 동시에 반영됩니다. HTML은 건드리지 않습니다.

```js
{
  slug: 'session-sharing',      // URL에 쓰이는 값. 영문 소문자와 하이픈.
  category: '작업 방식 · 도달 범위',  // CATEGORIES에 있는 값이어야 하고, 같은 값끼리 붙여 둡니다.
  name: '세션 공유',
  summary: '장표에 한 줄로 보일 설명',
  why: '이 항목을 왜 보는지 + 무엇을 기준으로 판정했는지 (상세 페이지 상단)',
  tools: {
    bob: {
      level: 'full',                                  // full | partial | none | unknown
      label: '표에 보일 짧은 요약',
      bullets: ['근거 한 줄', '근거 한 줄'],
      media: { src: 'assets/img/session-sharing/bob.png', caption: '설명' },
      source: { text: '출처 이름 (등급을 이름에 드러냅니다)', url: 'https://...' },
    },
    claude: { /* 동일 */ }, codex: { /* 동일 */ }, cursor: { /* 동일 */ },
  },
  verdict: '상세 페이지 하단 정리. 기준에 의존하는 우위라면 그 사실을 여기 적습니다.',
}
```

**화면 / 영상**은 `public/assets/img/<slug>/<도구 id>.<png|mp4>`에 넣으면 상세 페이지의
"준비 중" 자리 표시가 자동으로 바뀝니다. 도구 id는 `bob`, `claude`, `codex`, `cursor`입니다.

**도구 로고**는 현재 브랜드 색 글자 마크로 대체돼 있습니다. 각 벤더의 공식 SVG를
`public/assets/img/logo/<도구 id>.svg`에 넣으면 자동으로 교체됩니다. 파일이 없으면 글자 마크가
그대로 남으므로 넣기 전에도 화면은 깨지지 않습니다.

```
public/assets/img/logo/bob.svg
public/assets/img/logo/claude.svg
public/assets/img/logo/codex.svg
public/assets/img/logo/cursor.svg
```

로고는 28×28 정사각 영역에 `object-fit: contain`으로 들어갑니다. 여백이 없는 심볼 마크가
가장 잘 맞습니다.

## 판정 규칙

이 자료의 가치는 정확도에서만 나옵니다. 검토자가 한 칸이라도 틀린 것을 발견하면 나머지 22개 항목도
믿지 않습니다. 그래서 규칙을 지키는 편이 표를 좋게 만드는 것보다 우선합니다.

**1. 근거 없는 판정을 적지 않습니다.**
`full`·`partial`·`none`으로 적은 칸에는 `source`가 반드시 있어야 합니다. 못 찾으면 `unknown`으로
비워 둡니다. 빈 칸은 "기능이 없다"가 아니라 "아직 확인하지 못했다"는 뜻입니다.

**2. 출처는 주장별로 개별 문서를 겁니다.**
문서 개요 페이지 하나를 여러 칸에 재사용하면 규칙의 글자만 지키고 뜻을 어깁니다. 초안에서
`SRC.claude` 한 개가 열 칸의 근거로 쓰이고 있었습니다.

**3. 출처 이름에 근거 등급을 드러냅니다.**
`공식 문서` > `사내 발표자료`·`벤더 발표` > `보도` 순입니다. `(벤더 발표)`, `(보도)`, `(사내)`를
이름에 붙여 클릭하지 않고도 무게를 알 수 있게 합니다.

**4. 등급을 도구 간에 맞춥니다.**
한 도구를 발표자료로 판정하고 다른 도구를 문서 첫 페이지로 판정하면, 판정 차이가 기능 차이가 아니라
조사 밀도 차이가 됩니다. **이 자료에서 가장 자주 나온 실수입니다.** 새 항목을 넣을 때 네 칸의 출처
등급이 비슷한지 먼저 확인하세요.

**5. `none`은 벤더 문서가 부재를 명시한 경우에만 씁니다.**
찾지 못한 것과 없는 것은 다릅니다. 현재 `none`인 칸은 `sandboxing`의 Bob 하나이며, 근거는 공식
보안 가이드가 "`.bobignore`는 시스템 수준 샌드박스를 만들지 않는다"고 직접 밝힌 문장입니다.

**6. Bob에 유리하게 임의로 판정하지 않습니다.**
타 도구가 더 나은 항목은 그대로 표기합니다. 현재 Bob이 뒤지는 행이 11개, 단독 우위인 행이 3개입니다.

**7. 기준을 바꾸면 결론이 바뀌는 항목은 그 사실을 `verdict`에 적습니다.**
예를 들어 `code-review`는 "지적 사항이 목록으로 남는가"로 물으면 Bob이 앞서지만, "사람이 잊어도
리뷰가 도는가"로 물으면 뒤집힙니다. 기준에 의존하는 우위를 절대적 우위처럼 적으면 그것이 편향입니다.

### 축을 새로 넣거나 뺄 때

**빼는 이유가 한 도구에 유리한 방향으로 치우치지 않는지 확인하세요.** 초안은 `인터페이스 형태`를
"제품 사양이지 역량이 아니다"라는 이유로, `Skills·커스텀 워크플로`를 "MCP와 겹친다"는 이유로 뺐는데,
두 근거 모두 틀렸고 빠진 영역이 정확히 Bob이 가장 약한 지점이었습니다. 자세한 경위는
[PLAN.md 4.1](PLAN.md)에 있습니다.

카테고리를 새로 만들 때는 `CATEGORIES`에 **답하는 질문**을 함께 등록해야 합니다. 표의 그룹 머리행과
상세 페이지 목록이 이 질문을 함께 표시합니다. 등록하지 않으면 질문 없이 이름만 나옵니다.

```js
const CATEGORIES = {
  '작업 방식 · 도달 범위': '언제, 어디서 일을 맡길 수 있는가',
};
```

같은 카테고리의 항목은 `FEATURES` 배열에서 **연속으로** 두어야 합니다. 렌더가 카테고리가 바뀌는
지점마다 그룹을 새로 열기 때문에, 떨어져 있으면 같은 카테고리가 두 번 나옵니다.

`internal-src/`의 사내 자료를 인용할 때는 `SRC`에 `url: null`인 항목으로 넣습니다. 링크가 없는
출처는 상세 페이지가 이름만 표시합니다.
